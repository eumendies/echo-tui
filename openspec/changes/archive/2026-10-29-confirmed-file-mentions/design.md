## Context

当前 `parseFileMentions()` 扫描所有 `@`，把后续到空白或闭合双引号的字符当作路径。`renderComposer()` 和 `expandFileMentionsForUserText()` 分别在重绘和提交时重新扫描相同文本，没有“用户已确认”的状态。

file picker 已有 Enter 确认、多选和路径格式化，但 `confirm()` 只替换文本。composer 仅保存 grapheme 数组与光标，输入历史及 pending 仅保存字符串；steer 在消费草稿后异步准备文件。若只修改高亮，不修改这些路径，会出现不高亮却读取文件、排队后引用丢失、异步读取后来草稿等不一致。

本设计保留纯文本编辑、ANSI/raw mode、现有 footer surface 和 provider 附件转换，不引入富文本编辑器或新依赖。

## Goals / Non-Goals

**Goals:**

- 文件引用只来自用户在 file picker 中显式 Enter 确认。
- 高亮范围、读取路径和用户确认意图使用同一事实来源。
- 普通文本中的 `@` 不误高亮、不引发 mention 自动读取；邮箱和粘贴不抢占输入。
- 对文本编辑、Unicode、输入历史、pending、steer 和失败恢复定义确定行为。

**Non-Goals:**

- 不实现不可拆分 chip、整块退格删除、文件图标或新的引用管理面板。
- 不新增全文路径解析、递归模糊搜索、任意手写路径一键转换或额外快捷键；现有 query/目录浏览能力保持原样。
- 不新增跨重启的草稿或引用元数据持久化，不改 transcript/provider 协议。
- 不改变 agent 自行调用 `read_files` 的能力；本变更只控制输入 mention 的自动附带行为。
- 不改变文件读取安全限制、图片压缩设置、审批和 surface 优先级。

## Decisions

### 1. 将已确认引用保存为 composer 元数据

在 composer 中保存已确认引用集合，每项包含 `start`、`end` 和 `path`：

- `[start, end)` 使用与 composer 相同的 grapheme cluster 下标，包含 `@` 和路径显示文本，不包含分隔空格。
- `path` 是确认时选择的实际路径；提交直接使用它，而不是从显示文本再次推断。
- 范围有序、不重叠，引用只由选择器确认或可信内部快照恢复建立。
- `formatFileMention()` 保留当前 `@path` / `@"path with spaces"` 外观。文件名中的中文、标点、`@` 均按已知范围显示，不再承担语法分隔职责。

不使用文本正则或“路径存在才高亮”：它们不能区分用户意图，后者还会把文件系统访问带入重绘。也不把引用做成不可拆分 token，以免扩展所有光标和删除操作。

### 2. 用统一的编辑规则维护范围

所有真实文本变更收敛到能够维护引用范围的编辑逻辑，覆盖插入、替换、Backspace、Delete、删词、删行和换行；不允许各调用点直接改字符数组后遗漏引用更新。

对原引用 `[s, e)` 和普通编辑操作，约定如下：

| 编辑位置 | 行为 |
| --- | --- |
| 在 `s` 处插入 | 视为引用前插入，引用整体右移 |
| 在 `e` 处插入 | 视为引用后插入，引用保持原范围 |
| 严格位于 `s < p < e` 的插入 | 撤销该引用，按普通文本保留编辑结果 |
| 非空删除/替换区间与 `[s, e)` 相交 | 撤销所有被相交的引用 |
| 完全位于引用之前的删除/替换 | 按 grapheme 长度变化平移引用 |
| 完全位于引用之后的编辑 | 引用不变 |
| 仅移动光标或重绘 | 引用不变 |

删除恰好位于引用后的尾随空格不会撤销引用。此后追加“说明”、标点或另一个 `@` 都不扩大原引用范围。编辑后恢复出相同路径文本也不自动重新确认。

整段 `setText()` 默认创建普通文本并清除旧引用；`reset()` 同时清空文本和引用。内部快照恢复与普通 `setText()` 语义区分，避免任意字符串获得引用资格。长度和偏移必须与实际编辑后的 grapheme 数组一致，测试覆盖组合字符边界，不能以 UTF-16 长度代替。

无已确认引用时，不需要构造全文的旧/新坐标表：保留编辑点前已稳定的 grapheme 前缀，仅从前一个 cluster 开始重分段后缀。普通末尾输入只处理最后一个 cluster 和新增文本；有引用时仍使用完整坐标映射维护范围。该优化不引入缓存或另一套 Unicode 判定规则。

### 3. 触发与确认分离，并保留粘贴来源

仅当普通/计划输入态收到非粘贴来源的独立 `@`，且光标位于文本开头或前一个 grapheme 是空白、并且不在已有引用内部时，打开选择器。`a@b.com`、`pkg@version`、`请看@这里` 都不打开；中文描述需使用 `请看 @`。

当前 bracketed paste 最终产生普通 TEXT，单字符 `@` 的粘贴与键入无法区分。因此输入解析需为 bracketed paste 的 TEXT 保留来源标记，并让触发逻辑读取该标记；不能仅凭 `value.length > 1` 猜测粘贴。现有非 bracketed paste 终端无法可靠区分逐字粘贴与键入，本变更不以 stdin chunk 边界猜测；但无论何种来源，没有 Enter 确认都不会建立引用。

孤立 ESC 既可能是取消键，也可能是粘贴起始标记的首字节。运行时为孤立 ESC 保留 30ms 判别窗口：下一包及时到达时继续解析完整序列，否则交付 Esc；退出/更新交还终端时取消待定交付。刷新接口只返回单个事件或空值，不为至多一个取消事件引入数组交付。已收到 `ESC[` 等确定前缀时继续沿用跨 chunk 缓冲，不用超时猜测完整粘贴内容。

选择器中的 query 仍是普通文本，不高亮为已确认引用。Space 只切换选中项，鼠标只浏览/选择，Enter 才将 trigger range 原子替换为显示文本和引用集合。Esc 保留 `@query`，不建立引用。

```text
普通文本 -- 合法位置键入 @ --> 查询中 -- Enter 确认 --> 已确认引用
                                |                       |
                                Esc                     内部编辑
                                v                       v
                             普通文本                普通文本
```

### 4. 渲染只投影引用范围，提交只读取显式路径

`renderComposer()` 消费 composer 中的引用范围，按现有强调色渲染。渲染不调用文本 mention 解析器，不访问文件系统。

文件展开入口接收原始文本和显式确认的路径集合；无引用或未提供引用时只返回原文。路径去重、读取时机、错误格式、目录/PDF/图片支持、压缩和 provider converter 保持现有语义。确认后文件被删除仍保留强调色，提交时按原有错误策略处理；高亮表示确认意图，不保证文件持续存在。

同一条消息里，即使普通文本与已确认引用显示完全相同，也只使用已确认项的元数据；不扫描命令展开、skill/workflow 模板或会话引用内容中的 `@`。命令路径保留用户原草稿中明确确认的文件集合，但不把原草稿的位置索引套到命令转换后的文本；从原草稿快照取得显式路径后再交给现有素材准备流程。命令直接 handled 和 shell/shell-local 路由仍优先，不因残留引用元数据触发文件读取。

### 5. 以草稿快照贯穿提交生命周期

引入内部草稿快照语义：原始文本及其已确认引用的独立副本；光标用于需要恢复的 live 草稿。具体类型可在实现时按现有模块边界命名，不新增通用状态框架。

- 接收 Enter 时，在清空 composer 前同步捕获快照；消费、历史和提交使用该快照，不再只传字符串。
- pending 只保存自己的确认路径数组副本，不保存派发时不使用的文本范围；实际 dispatch 时才读取文件，B 草稿的输入、清空和引用变更都不能修改 pending A。
- steer 准备直接使用局部接收快照的引用集合，槽位不再重复保存引用；准备完成后的 record 独占文件素材，移交沿用既有一次性交付，不重读文件。
- 单槽已占用或提交被阻止时，原草稿、光标和引用全部保留。
- 引用准备失败或取消时，如果原逻辑允许恢复且 live composer 尚空，则恢复原文本及引用；已输入的新草稿不被覆盖。
- 当前进程内输入历史统一保存快照，按历史索引恢复引用，不按文本内容匹配；相同文本的两条历史可以拥有不同的引用资格。对外字符串历史投影保持兼容，但内部不保留只为测试夹具服务的字符串/快照联合类型。
- 旧会话文本没有确认元数据，普通文本赋值只产生空引用草稿；如需进入历史，沿用相同的快照记录入口。当前没有旧字符串历史加载链路，不为假设的迁移维护另一套恢复分支。已持久化 user record 的展开内容和图片附件按原语义重放，不重新扫描读取。

不扩展持久化格式，是为了把当前体验修复控制在 transient 输入和提交边界内。需要跨会话恢复引用的能力可独立提案。

## Risks / Trade-offs

- [手写 `@path` 不再自动附带文件] → 作为有意的行为变化记录在用户文档中，继续提供选择器查询、浏览和 Enter 确认。
- [插入与删除实现分散，容易遗漏范围更新] → 收敛真实文本变更入口，以纯函数/控制器测试覆盖全部编辑操作和边界。
- [引用可被部分编辑，撤销后不再自动恢复] → 这是保留纯文本编辑模型的明确取舍；失去高亮即可表达需重新选择确认。
- [元数据在 pending、steer、命令转换或失败恢复时丢失/串用] → 使用独立快照并在提交边界转换成显式路径；以真实 handler/context 组合做集成测试。
- [旧历史重提不自动附带原文件] → 旧文本不猜测确认意图；已经持久化的原记录不变，当前会话内新历史可正确恢复引用。
- [终端不报告粘贴来源] → bracketed paste 场景严格抑制触发，不支持来源时不承诺区分；确认门槛始终有效。

## Migration Plan

1. 先建立引用元数据、编辑规则及草稿快照，再接入选择器确认和渲染。
2. 将普通提交、pending、steer、历史恢复和命令生成路径改为显式传递，移除自动扫描文本的生产调用。
3. 更新回归测试及用户说明，执行项目验证序列并手动验证终端交互。
4. 不迁移 transcript 或配置；回滚时回退此次实现即可，但会恢复旧的 `@` 误识别行为。

## Open Questions

无阻塞问题。当前会话历史保留引用、纯文本旧历史不推断引用，以及不扩展路径搜索均为本提案的明确范围决定；若审阅时希望改变，可在实现前调整。
