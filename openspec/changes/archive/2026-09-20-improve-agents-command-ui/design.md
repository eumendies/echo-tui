## Context

`/agents` 当前由 command handler 把管理快照投影为通用 `AgentsCommandRow[]`，再由专属 footer renderer 将每个 Agent 的来源、状态、capability、模型、effort、工具、Skills、MCP 和描述拼接为单行。该结构保留了完整业务信息，但在 80 列及更窄终端中只能展示多个被截断的片段；详情和表单同样使用无分区的连续双列行，动作与只读字段缺少视觉边界。

本变更只调整 command surface 的信息投影和 ANSI footer 渲染。管理存储、乐观冲突、覆盖优先级、确认流程、键盘状态机、Subagent catalog 冻结及下一轮生效语义保持不变。实现仍须遵守有限 footer 高度、真实终端光标、宽字符列宽计算、不使用 alternate screen 以及不引入第三方 TUI 库等约束。

## Goals / Non-Goals

**Goals:**

- 让用户在列表中优先识别 Agent 名称、来源、状态与 capability，再通过稳定摘要读取完整策略和描述。
- 在宽终端利用横向空间，在窄终端保持可读的上下信息层级，并始终保证当前焦点可见。
- 通过统一状态标记、统计和诊断语气降低扫描成本。
- 为详情和表单增加语义分区，明确区分只读信息、可编辑策略、普通动作和危险动作。
- 保持现有 controller 行为、焦点索引、确认安全默认值和真实光标编辑行为。

**Non-Goals:**

- 不改变 Agent manifest、内置 override sidecar 或任何磁盘路径与格式。
- 不改变 Agent 发现、校验、覆盖、执行权限、MCP、Skills 或模型策略语义。
- 不增加搜索、过滤、排序、鼠标操作、快捷字符键或 Agent rename。
- 不统一重写所有 footer surface，也不引入通用布局框架或第三方依赖。

## Decisions

### 1. 列表与详情采用渐进披露，而不是继续扩展单行

列表中的 Agent 行只保留名称、短状态、来源和 capability。当前选中 Agent 的 model、effort、工具数量、Skill 策略、MCP、description、来源路径及诊断投影到独立摘要。这样列表负责定位，摘要负责解释，避免同一行内多个长字段相互争夺宽度。

备选方案是把每个 Agent 固定渲染为两到三行卡片。该方案改动较小，但会显著减少有限 footer 中可见的 Agent 数量，而且多个卡片仍会重复相同的策略标签，因此不采用。

### 2. handler 输出语义化摘要，renderer 不重新推导业务状态

`AgentsCommandSurface` 增加当前选中项摘要和范围统计投影；摘要由 `createAgentsSurface` 基于当前 rows 与管理快照创建。摘要使用结构化字段表达身份、运行策略、权限摘要、描述和诊断，renderer 只负责布局、裁剪和 theme token，不自行读取 snapshot 或判断覆盖优先级。

列表与事件处理继续使用现有扁平 `rows` 和 `selectedIndex`，避免为纯展示变化重写 controller 状态机。新建等动作被选中时，摘要改为展示动作说明；普通诊断行被选中时展示完整有界诊断。这样所有可聚焦行都有稳定的辅助信息，而不会出现沿用上一 Agent 摘要的错觉。

### 3. 仅列表模式使用响应式主从布局

在可用宽度达到约 96 列时，列表模式使用左右分栏：左侧是选中窗口，右侧是选中项摘要。更窄时使用上下堆叠：先显示列表窗口，再显示带分隔标题的紧凑摘要。具体断点由 renderer 常量集中定义，并以 `safeRenderWidth` 和 `displayWidth` 计算，不能依赖字符串长度。

详情、表单、Tools、Skills、instructions 和确认模式保持全宽，避免编辑态因宽度变化造成字段位置和真实光标跳到另一栏。终端 resize 后只重新投影布局，不修改 `selectedIndex`、草稿或编辑光标。

高度预算先扣除边框、Tab、消息和提示；列表必须保留当前选中行，摘要优先保留身份及状态，再保留策略字段，长 description、路径和诊断最后裁剪。若高度不足以同时展示全部内容，则使用“更多”标记并允许 Enter 进入现有详情查看，而不是隐藏选中行或突破 `maxLines`。

### 4. 使用状态符号、短中文标签和顶部统计建立视觉层级

renderer 将 canonical status 映射为稳定的短标签和 theme tone，例如生效、被覆盖、无效与保留；符号只是冗余视觉编码，文本标签必须始终存在，不能仅依赖颜色。Tab 展示标签改为中文，但内部 `overview`、`project`、`user`、`builtin` ID 保持不变。

顶栏右侧显示当前范围的简短计数，例如“3 生效 · 1 异常”。状态、来源和 capability 不再以全部大写长串展示。未知 status 必须安全显示其规范化文本，避免新增状态被静默误报。

### 5. 通过行分区元数据渲染详情与表单

详情和表单 rows 增加可选的 section 元数据，首个属于某 section 的可见行之前渲染分区标题。预期分区为“身份”“运行策略”“能力与权限”“操作”；确认、Tools、Skills 和 instructions 子页面继续使用其专属布局。

section 标题不参与 controller 的 `selectedIndex`，因此不会改变上下键和 Enter 的目标。窗口计算以可聚焦 rows 为基础，再把可见 section 标题计入最终行预算，确保选中行仍在窗口中。危险动作使用 danger tone，并与保存、取消等普通动作在“操作”区中保持明确区分。

实现优先复用 `config-panel-rows.ts` 中已经验证的边框、section、双列和动作行原语；若其宽度约定或真实光标假设与 `/agents` 不兼容，则提取最小公共纯函数，而不是添加只做转发的抽象层。

### 6. 保持现有交互和持久化测试，增加信息投影测试

command handler 测试继续验证 Tab、Enter、Esc、确认、冲突和草稿行为，并增加摘要、统计及 section 元数据断言。renderer 测试覆盖宽屏分栏、80 列上下布局、窄终端截断、有限高度、长宽字符、异常与 shadowed 状态、动作摘要、分区窗口和编辑光标。

渲染断言以关键语义、可见宽度和焦点可见性为主，不对整屏 ANSI 字节流做脆弱快照。

## Risks / Trade-offs

- [摘要占用垂直空间，窄终端可见列表项减少] → 使用选中窗口、紧凑字段组合和优先级裁剪；极低高度时保留选中行及核心摘要。
- [左右分栏和上下布局可能产生行为差异] → 两种布局消费同一 surface 摘要，只改变 renderer 排版，并为 resize 前后相同选中项增加测试。
- [section 标题导致 `maxLines` 预算计算复杂] → 标题不进入业务 rows；窗口选择后统一计算附加标题，并在超出预算时从非选中端收缩窗口。
- [状态中文化可能掩盖未来未知状态] → 已知状态使用显式映射，未知状态展示经过控制字符清理的原值并使用中性或警告 tone。
- [复用配置面板原语可能牵连其他 surface] → 优先保持公共函数兼容；如需改变签名，增加对应 `/config`、`/mcp` 回归测试，避免视觉优化扩大为全局重构。
- [摘要与详情重复信息] → 摘要只提供快速判断所需的有界内容，详情继续承载完整路径、来源和可操作项。

## Migration Plan

1. 先扩展 surface 类型与 handler 投影，并更新 controller 测试；此阶段不改变存储或 runtime。
2. 重构列表 renderer，加入统计、状态标签、摘要和响应式布局。
3. 为详情与表单加入 section 元数据和分区渲染，最后校准有限高度与真实光标。
4. 运行类型检查、完整测试和 JavaScript 语法检查，并手动验证 50、80、96、120 列及 resize 场景。

该变更没有数据迁移。若需要回滚，只需恢复旧 surface 投影与 renderer；磁盘中的 Agent 定义和 settings 不受影响。

## Open Questions

- 宽屏断点最终采用 96 列还是根据摘要最小列宽动态计算，可在实现时通过 80/96/120 列渲染测试确定。
- 极低 footer 高度下，摘要保留两行还是三行核心信息，需要结合主 renderer 实际传入的 `maxLines` 下限校准。
