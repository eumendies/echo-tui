## Context

当前 `apply_patch` 将 patch 解析为有序的文件操作，但模拟器会在首次解析出绝对路径后将其加入去重集合；同一路径的后续操作会在模拟前失败。各操作也直接从真实文件系统读取目标，因此仅移除去重不能使删除后的新增或前序更新后的再次更新生效。

现有流程在全部模拟成功后才写盘，并由 change recorder 在每个实际写入前后记录快照。这是 `all-or-nothing` 校验、部分写盘失败的回退记录以及 `/undo` 的基础，必须保留。

## Goals / Non-Goals

**Goals:**

- 支持一个 patch 内同一解析后绝对路径的有序 `add`、`update`、`delete` 操作。
- 使每个操作基于该请求内此路径的前序模拟状态。
- 保持现有安全检查、hunk 语义、最终写盘边界与 change history 可回退性。
- 将每个路径的最终状态一次交给写盘层，避免删除后新增产生不必要的真实文件系统中间状态。

**Non-Goals:**

- 不支持 rename、move、copy、mode、二进制或 symlink patch。
- 不改变跨多个独立 `apply_patch` tool call 的语义。
- 不改变 provider 参数结构、权限审批或渲染协议。

## Decisions

### 按绝对路径维护虚拟文件状态

模拟器将以规范化绝对路径为键保存首次访问时的原始状态及当前虚拟状态。首次访问仍从磁盘读取并应用 UTF-8、普通文件、symlink、大小和 NUL 校验；后续操作只读取该虚拟状态。这样相对路径和绝对路径指向同一文件时也共享同一序列。

替代方案是移除去重后按操作立即写盘。该方案会破坏模拟失败零写入语义，并在删除与重建间留下磁盘中间状态，因此不采用。

### 将操作合法性基于虚拟当前状态判断

`add` 仅在虚拟状态不存在时成功；`update` 和 `delete` 仅在虚拟状态存在且已通过首次读取安全校验时成功。更新 hunk 和删除 hunk 针对虚拟当前内容匹配。故 `delete → add`、`update → update`、`add → update`、`update → delete` 可以工作，而 `add → add`、`delete → update` 等无效状态迁移继续失败。

### 只提交每个路径的最终有效变化

成功模拟后，写盘输入按首次遇到路径的稳定顺序输出每个路径的一项最终状态。原先存在、最终仍存在的文件视为更新；原先不存在、最终存在的文件视为新增；原先存在、最终不存在的文件视为删除；原始与最终均不存在的路径不写盘也不记录 change history。

这使 delete→add 对已有文件只产生一次写入和一份写前快照；`/undo` 可恢复调用前的内容。替代方案是保留逐操作写盘，虽能复用现有代码，却会造成重复 snapshot/write 和失败时的中间状态，故不采用。

### 保留操作级展示、最终状态级写盘摘要

模拟器继续为每个成功操作生成 display metadata，使 transcript 可显示删除和新增这一模型实际请求的序列；changed-files summary 与写盘集合则按最终路径状态去重。这样不要求渲染层重新推断操作，也不会将操作级 metadata 当作写入成功证明。

## Risks / Trade-offs

- [虚拟状态与真实文件状态表达混淆] → 为状态定义区分首次原始快照、当前存在性和当前内容，并让文件读取安全检查只在首次从磁盘装载时执行。
- [重复路径绕过文件数量限制] → 保留 patch 字节数、hunk 数和操作数量限制；最终写盘仍按唯一路径处理。
- [展示与最终摘要不一致] → 明确展示是操作序列，摘要是最终文件集合，并为 delete→add 增加测试。
- [写盘部分失败] → 维持现有“单文件写入成功后立即标记”的 change recorder 调用顺序；未写入最终状态不得标记。

## Migration Plan

无需数据迁移或配置变更。发布后此前因重复目标路径失败的 patch 将成功执行。若发现行为回归，可恢复路径去重拒绝逻辑；该回退不影响磁盘格式、session 持久化或 provider 协议。
