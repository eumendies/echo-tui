## Context

主会话恢复先重放 journal，并根据 compaction 安装活跃后缀；`renderResizeRecovery()` 再把当前 owner 的记录交给 `renderDestructive()`。主会话路径过滤并行子 Agent 过程、pending 内部调用和重复压缩提示后，通过 `renderTranscriptLines()` 完整生成所有历史行，最终连同 banner、in-flight 内容和 footer 一次性写入终端。

当前 compaction 边界控制模型上下文和原始记录驻留，不适合作为终端历史量的唯一上限。普通新增内容已采用增量 append，主要优化点是恢复和破坏性重绘，不应给每次 footer tick 增加历史扫描。

临时基准使用当前渲染器、默认主题、120 列和四份真实历史，重复九次取中位数；约 1,000 行软预算的结果如下。A/B/C 已压缩，D 未压缩。脚本校验了全量分块输出与现有投影逐字符一致，预算结果为全量输出的完整块后缀。

## Goals / Non-Goals

**Goals:**

- 默认减少主会话历史重绘的昂贵排版和 ANSI 输出量，并允许用户在 `/config` 控制预算。
- 保持完整块语义、相对顺序、可见性过滤以及实时内容、footer 和光标的不变量。
- 只改变显示窗口，不改变模型输入、驻留边界、journal 或完整历史操作。
- 以明确的提示解释未展开历史，并提供“不限”退出路径。

**Non-Goals:**

- 不增加渲染缓存、journal checkpoint、历史分页、worker 排版或输出背压调度。
- 不实现严格的源文本/单块成本上限，不实现超长块折叠或 Markdown 块内截断。
- 不修改 BTW、子 Agent 独立视图、session 选择器预览及 headless 的既有范围。
- 不限制普通增量 append 后的终端 scrollback 总量，不新增“查看更多”命令或 alternate screen。

## Decisions

### D1：用户级独立显示配置，默认 1,000 行

新增 `ui.historyRenderLineLimit`，归一化到 `AppSettings` 和 `RenderPreferences`。有效值仅为 `500 | 1000 | 2000 | 5000 | 10000 | 0`；`0` 显示为“不限”，缺失或非法值独立回退 `1000`。首版采用明确档位而非任意数值编辑，减少配置交互复杂度，同时覆盖快恢复、较多回看和兼容旧行为三类需求。

在 `/config → 常规` 的显示相关设置附近增加“历史重绘预算”行，左右键在 `[500, 1000, 2000, 5000, 10000, 0]` 顺序上移动，到端点停留。选中时只用一行说明“控制恢复会话时渲染的消息行数，不影响模型上下文；回看受终端滚动历史上限限制”，不在 hint 中展开完整块、超限等实现细节。终端滚动历史（scrollback）上限与窗口高度不同：前者限制可保留并回看的输出，后者仅限制一屏可见的行数；预算不修改终端缓冲区配置。修改只作用于草稿，沿用显式保存、dirty 保护、原子写入和未知字段保留。

没有选择按 token/记录条数计量，因为它们不能稳定代表终端工作量；没有只取屏高倍数，因为主屏 scrollback 需要保留比三屏更多的回看空间。固定默认值可通过档位调整，不做机器速度自适应。

### D2：分组之后、昂贵排版之前做尾部选择

复用现有分组规则，明确拆开“识别完整渲染块”和“把块排版成行”两个步骤，不复制另一个工具/子 Agent 分组器。在这些块之上，仅将具有展示依赖的块合并为不可分的预算选择单元：若单委派外层结果因过程栏已包含报告而折叠，则将其依赖的驻留过程栏至该结果之间的连续块区间一起纳入；重叠依赖区间合并。这样不会保留只剩完成状态的折叠结果却省略其报告正文，也不需要发明新的结果展开模式。处理顺序为：

```text
主会话驻留 records
  → 全局轻量身份恢复和可见性过滤
  → 完整渲染块分组，并合并展示依赖区间
  → 从最新选择单元向前排版并累计实际行数，达到预算即停止
  → 将选中块恢复为历史顺序
  → banner + 压缩提示 + 预算提示 + 历史 + in-flight + footer
```

行数采用当前宽度、主题和 reasoning 偏好下的 `splitRenderedBlock` 行语义，包含消息块自身空行，不包含 banner、瞬时提示、in-flight/shell 投影或 footer。达到预算的整个边界单元保留，较早单元不再排版；不限使用全部可见候选块。隐藏 role、隐藏 reasoning 和已过滤的并行过程不消耗行预算。依赖合并仅使用现有驻留候选，不为已压缩过程回读 journal；并行子 Agent 的外层报告保持其既有非折叠规则。

预算投影只从 `renderPreferences.historyRenderLineLimit` 读取预算，不另设可覆盖该值的行数参数；省略 preferences 时沿用默认 1,000 行，只有显式 `0` 表示不限。app 层直接传递归一化 preferences，不重复兜底。

身份恢复还必须区分“完整记录中已知的 run/终态/并行关联”和“本次实际写出标题的 run”。前者可以来自全部活跃元数据，后者（现有 `runIds` 语义）必须按选中并输出的块重建；预算省略某个 run 后，它的新事件第一次进入屏幕时仍需带标题，不能被误认为已有标题的 continuation。

可以继续对活跃记录做 O(N) 的轻量扫描和身份分组；本次保证的是避免被跳过正文的 Markdown 解析、高亮、折行和 ANSI 文本构建，而不是把整条路径宣称为 O(预算)。不得先调用全量 `renderTranscriptLines()` 再截取行，也不得为精确统计省略行数补做全量排版。

### D3：软预算与完整块优先，明确单块例外

完整块沿用现有 transcript 分组语义，包括普通消息、相邻工具 call/result 对和连续子 Agent run 分组；仅有 D2 所述展示依赖时合并连续区间作为更大的选择单元，不以整轮 user turn 为固定单位，也不引入块内 Markdown 重新切分。

例如预算 1,000 行，最新块为 600 行、前一块为 700 行，则保留两块共 1,300 行。若最新块本身为 5,000 行，则完整保留这一个块并停止向前选择。因此预算可以显著降低多块长历史的成本，但不承诺限制单个超长消息/子 Agent 分组的成本。

拒绝“硬切最后 N 行”，因为它既可能先付出全量排版成本，又可能丢失工具调用标题、代码块或消息边界；源文本预算和超长块折叠留作独立后续变更。

### D4：预算只约束主会话稳定历史投影

在当前 owner 为 main 的破坏性重绘应用预算，包括 `/resume`、resize、主题/显示偏好变化、Undo 后恢复、离开 BTW/子 Agent 视图回到主会话。已压缩会话只从驻留活跃后缀选择；未压缩会话从全部当前记录选择。不限也不绕过现有 compaction 边界。

普通 `renderRecords()`、流式稳定前缀提交和 footer 局部重绘保持现状。会话继续输出后，原生 scrollback 可以多于配置预算；直到下一次破坏性恢复才重新选择后缀。不为维持行数主动清屏、不重新扫描全部历史、不阻止最新内容显示。

BTW/子 Agent 独立视图保留已有完整投影语义，不将主会话预算传成它们的裁剪条件。in-flight assistant/reasoning/shell 已确定投影与 pending 尾部保留既有恢复边界，当前流式段不被稳定历史预算裁掉。

### D5：瞬时提示，不伪造历史事实

只有预算确实排除了更早的可见候选块时显示一条低强调提示，例如：

> 较早的部分历史未展开，未删除记录且不影响模型上下文；可在 /config → 常规 调整历史重绘预算或选择不限。

提示不报告无法廉价获得的精确省略行数，不暗示内容被 compaction、不进入 provider、journal、copy 或完整记录计数。与现有压缩提示分别表达不同边界，均最多显示一次。若全部可见内容已纳入（即使单块超过预算），不显示预算省略提示；仅有不可见 role 的旧前缀也不应造成误导提示。

### D6：保存/外部修改即时生效，避免无关重绘

复用实例级配置 snapshot 和现有设置差异通知。预算的有效值变化且 main 正在显示时，触发一次按新预算的破坏性重绘；配置面板继续保持打开，焦点/草稿及 footer 光标按现有规则恢复。相同归一化值不触发重绘，保存后的同值 watcher 通知不重复恢复。

若仅预算变化且当前显示 BTW/子 Agent 视图，只更新设置，返回主会话时使用新值，不用主历史覆盖当前 owner。与 reasoning/主题等变化共现时按既有 owner 仲裁合并重绘。普通渲染路径不读配置文件，预算变化不清理 context usage、不重启或中断 active assistant run。

### D7：验证性能结构，不把机器耗时写成 CI 门槛

- 纯投影测试确认输出等于既有可见历史的完整块后缀，保留分组状态和空行语义；不限/历史不足时与旧输出等价。
- 使用真实 runtime 组合、模块级现有边界或不应被访问正文的 fixture，证明预算以外的正文未被昂贵排版；不增加仅供测试的生产 callback/开关。
- 确定性长历史基准记录全量/500/1,000/2,000 行的耗时、实际行数和 UTF-8 输出量。热身后重复测量，区分 journal、排版与终端；不硬编码 4–6ms 或加速倍数断言。
- 手工在真实 TTY 验证恢复、resize、配置保存、流式中恢复和 Ctrl+C/Ctrl+D 清理。

## Risks / Trade-offs

- [单块或展示依赖区间巨大仍可能慢且超出行数] → 明确软预算语义和非目标；保留完整展示依赖，避免本次扩大到块内折叠。复测应覆盖关联分组，不能把原始逐块基准直接当作所有分组的保证。
- [恢复后原生向上滚动看不到被省略内容] → 瞬时说明并提供调大/不限；不声称原生滚到顶部会自动加载。
- [逆序排版可能破坏子 Agent 关联] → 先基于完整驻留元数据完成过滤和分组，只对稳定的完整块做逆序选择，最后恢复原顺序；测试单委派、并行、pending 和中断终态。
- [少数块预算结果超过预设较多] → 在配置说明中明确“约”和完整块策略，不把档位称为硬上限。
- [默认范围变化影响用户预期] → 发布/配置文档说明默认 1,000 行及不限退出方式，保持所有原始历史操作不变。
- [终端输出等待或 journal 重放仍是瓶颈] → 分阶段复测，不把排版加速倍数等同于端到端 resume 加速。

## Migration Plan

1. 在取得实施确认后，增加可选配置字段和默认值，无需迁移或重写现有配置和 journal。
2. 接入配置 UI、snapshot 刷新和主会话历史投影，补齐测试与用户文档。
3. 依次运行 typecheck、完整测试及 JS 语法检查，再执行针对性 TTY 验证和性能复测。
4. 用户选择“不限”即可恢复原活跃历史展示范围；回退旧版本时该可选字段应作为未知配置保留，不产生存储迁移风险。

## Open Questions

无阻塞性问题。首版明确采用软预算、固定档位和主会话范围；单块硬限制、BTW/子 Agent 预算、缓存及历史分页均不在本次实施范围内。
