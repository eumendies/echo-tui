## Context

`TranscriptContext` 已在内存中维护并在 session journal 中持久化 `CompactionState` 与 `TodoState`。`/status` 目前经由 status command port 取得一次运行状态快照，并在同一只读 surface 内异步更新账户用量；其 renderer 将所有内容顺序拼接，在高度受限时从头部裁剪。因此，直接追加摘要正文和 todo 列表会挤掉运行状态，也不能阅读长内容。

本变更仅把既有会话状态投影到交互式 TUI，不修改压缩生成、todo 工具、session journal 或 provider 请求的行为。

## Goals / Non-Goals

**Goals:**

- 在 `/status` 中以可读且可导航的方式查看当前 session 的 compaction 摘要和 todo 列表。
- 让运行信息与远程账户用量继续可见，且不被长摘要或长任务列表淹没。
- 在 assistant turn 期间保持安全：读取状态不写入 transcript，也不干扰工具和异步用量查询。
- 复用既有 ANSI footer、主题、safe render width 和高度预算机制。

**Non-Goals:**

- 不在 `/status` 内创建、编辑、完成或重新排序 todo。
- 不保存 compaction 历史版本，不从原始 transcript 重建历史摘要。
- 不为 status surface 引入自动轮询、后台订阅或新的远程请求。
- 不改变 `CompactionState`、`TodoState` 和 session JSONL journal 的 schema。

## Decisions

### 使用三页只读页面而非单张追加卡片

status command session 新增当前页面和各详情页视觉行偏移。页面固定为“概览、压缩摘要、Todo”，打开时进入概览；概览保留现有运行信息与账户用量，并仅显示压缩和 todo 的短摘要。`←/→` 切换页面；详情页以 `↑/↓` 逐行、`Page Up/Page Down` 按可视区域滚动，`Home/End` 跳至边界。切换页面时保留各自滚动位置。

选择页面而不是将所有区块堆叠在一张卡片，原因是现有 status 在低行数下从头部裁剪；单卡片会使最重要的元信息或摘要正文不可达。将三页共用的页签、边框和操作提示固定，仅让正文区域窗口化，能在任意高度下维持导航上下文。

替代方案：在概览尾部增加折叠区块。未采用，因为需维护多个展开状态，且仍难以为两个长正文分配稳定的有限 footer 行数。

### 通过 status port 创建会话状态的防御性快照

扩展现有 `createStatusSnapshot()`，从 `TranscriptContext` 复制当前 compaction 和 todo 数据，并同时保留原有运行信息。surface 与 command session 只持有复制后的快照，不持有可变 context 对象引用；这避免渲染过程观察到部分状态更新，也保持 status 的只读边界。

`r` 仅重新创建本地 status 快照，用于读取 assistant turn 中最新的 compaction/todo 变化；刷新保持当前页面，保留详情页的偏移并将其钳制到新正文范围。它不重新发起 Codex、DeepSeek 或 OpenCode Go 的账户查询，避免用户为阅读本地计划而触发额外网络请求。初次打开时已有的账户异步查询和 requestId 过期保护保持不变。

替代方案：每次 todo 回调或压缩完成时自动刷新已打开的 surface。未采用，因为正文会在阅读中跳动，并需要新的 command session 更新订阅和生命周期清理。

### 摘要按格式化后的视觉行滚动，保留元信息

压缩摘要页面固定展示创建时间和 `activeStartIndex` 所代表的压缩边界；正文使用项目现有 Markdown/换行投影能力按卡片内容宽度换行，再以视觉行偏移窗口化。标题、列表和段落语义应保留，避免把多行摘要压缩成单行或只展示截断前缀。无 compaction 时展示稳定空状态。

`activeStartIndex` 只作为“压缩边界前已纳入摘要的记录数”展示，不能表述为压缩次数或对话轮数。此页面展示的是当前生效的滚动摘要，不宣称包含压缩边界之后的完整活动 transcript。

替代方案：直接使用 `clampPlainText` 显示摘要。未采用，因为其单行裁剪会丢失长摘要的大部分内容，不能满足查看需求。

### Todo 保持原顺序并用文字和主题语义同时表达状态

Todo 页面从快照的完整 `TodoState.items` 生成视觉行，按原有顺序显示，首行给出待办/完成/总数与更新时间。每项使用 `○ 待办` 或 `● 已完成` 等非颜色状态标识，并结合 normal/muted 等主题语义；长文本采用悬挂缩进换行，完成项不移动位置。页面只读，不设置可选择的任务行，避免与 agent 管理 todo 状态的权威来源发生冲突。

替代方案：只显示未完成 todo。未采用，因为用户明确需要查看当前 todo 内容，完成项能说明计划进度并与 session 状态保持一致。

### 将布局预算作为正文窗口的输入

renderer 先保留卡片边框、页签、页面元信息和提示行，再用剩余行数计算正文可见窗口；宽度继续使用 `safeRenderWidth`，正文在卡片内宽度换行。高度过小而无法容纳完整元信息时，详情页先将元信息压缩为单行，再依次移除分隔线、标题和非必要元信息；不得在构造完整卡片后从头部裁剪，否则会丢失当前页签和操作提示。窄宽度下，完整三页签无法放入卡片时使用带左右方向提示的当前页紧凑标签；Todo 状态标识也按正文宽度降级为符号。Todo 文本中的显式换行必须投影为独立的物理行。所有降级路径都不得产生末列自动换行、负行数、失效 cursor 或越界滚动偏移。概览中的用量区块继续遵守现有低行数降级规则。

### 概览运行信息使用固定的视觉标签列

概览页继续按既有顺序展示目录、模型、Provider、Session、Instructions、Memory、沙箱、压缩摘要和 Todo，不改为卡片、双栏或省略这些字段。每一行改由共享 key/value formatter 生成：标签列按当前概览标签的最大可见宽度预留，使所有 value 从相同终端列开始；宽度不足时标签列在最小宽度与可用内容宽度之间收敛，value 仍沿用现有安全裁剪。

选择这个方案是为了只修复截图中标签宽度不一造成的视觉锯齿，不改变用户既有的阅读顺序、字段语义或小终端下优先保留账户用量的行为。

## Risks / Trade-offs

- [长 Markdown 摘要在窄终端产生大量视觉行] → 使用已投影视觉行作为滚动单位，并显示当前位置/总行数，避免用户误以为内容被截断。
- [刷新后摘要或 todo 缩短导致偏移越界] → 每次刷新和渲染时钳制偏移；若内容为空则稳定为 0。
- [账户查询在详情页打开后返回] → 延续现有 handler/session/requestId 校验；更新账户数据不改变当前页面或详情滚动位置。
- [assistant 正在更新 todo 时用户阅读旧快照] → 明确使用打开时快照，提供 `r` 手动刷新，避免无提示的页面跳动。
- [现有 status renderer 较长且账户用量布局复杂] → 将页面投影和窗口化逻辑拆成小型纯函数，优先为快照、导航、行投影和布局边界添加单元测试。
- [固定标签列在窄终端挤压 value] → 标签列按可用内容宽度动态收窄，并继续通过 safe render width 和文本裁剪避免末列自动换行。
- [详情页固定框架在低高度被尾裁剪] → 在投影阶段按行预算生成完整或紧凑框架，不再依赖尾裁剪移除标题和页签。
- [页签、Todo marker 或任务换行破坏物理行边界] → 根据卡片正文宽度选择紧凑文案，并把 Todo 的每个源换行单独投影为视觉行。
