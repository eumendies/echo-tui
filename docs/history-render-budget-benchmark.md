# 历史重绘预算基准结果

本报告保留已完成的基准测量结果。测量只覆盖可分享合成历史的**主会话历史排版路径**，不是 `/resume` 端到端测试，未读取私人会话，也未将历史写到终端。

开发基准脚本已删除；下文仅记录当时的 fixture、测量口径和结果，不再提供可执行的复测入口。四个测量预算为 **全量（0）、500、1000、2000**，不设时间门槛，也未自动加入 `npm test` 或 CI。

## Fixture 与测量口径

- 共享生成器：`test/fixtures/history-render-budget.js` 的 `createHistoryRenderBudgetFixture({turnCount})`。它只由固定文本和序号生成数据，无时钟、随机数、用户配置、网络或本地 session 依赖。工具命令/路径仅是数据，不会执行；不提交合成 journal 或私人会话。
- 默认版本 `history-render-budget-v1`：240 轮、2,163 条驻留记录。包含中英混排/emoji、Markdown、代码/表格、reasoning、普通工具对、shell/error/local notice、不可见 role、30 次单委派及 15 组双并行委派。单委派报告、终态和外层折叠结果之间有其他消息，覆盖连续展示依赖区间，而非把每条 record 独立截取。尾部还包含活跃 run 和由 footer 承载的 pending 内部调用。
- 每次计时从新建子 Agent append 状态开始，按全部驻留元数据恢复身份，**先过滤 parallel 过程和 pending 内部调用，再调用 `renderBudgetedTranscriptLines`**；默认过滤后有 2,072 条待投影记录（仍含不可见 role）。随后完成可见性/分组、软预算尾部排版和 `lines.join('\n')` 的 ANSI 字符串拼接。全量档同样使用预算函数的 `0` 路径，不是旧实现的性能对比。
- 默认主题、120 列、显示 reasoning。返回行数组长度为实际行数，包含消息块自身空行；输出量为 `Buffer.byteLength(lines.join('\n'), 'utf8')`，包含 ANSI 转义字节、不额外追加末尾 LF，**不是字符串长度、去色文本字节数或完整恢复帧大小**。字节计数和断言在计时外执行。
- 先做结构校验，再为每档热身 3 次；每档测量 9 次，逐轮轮换四档的测量顺序，取中位数。保留自然分配/GC 开销，不强制 GC，也不清空 OS 文件缓存。生成 fixture、参考全量投影和报告输出均不计时。
- 测量时校验了 fixture 确定性且渲染前后不变、parallel/pending 已过滤、不限与既有全量投影逐行相同、有限输出是完整块后缀，以及从真实 fixture 提取的单委派依赖区间在极小预算下仍整体保留。每次采样核对实际行数/字节量一致；没有任何绝对耗时或加速倍数断言。

该优化仍可 O(N) 扫描轻量身份与分组元数据，不应宣称整条路径为 O(预算)。单个超长块或巨大的展示依赖区间仍可能超预算且耗时较高，下面的混合负载结果不构成它们的性能上限。

## 实测

2026-10-27（UTC），Apple M2、8 逻辑核、16 GiB 内存，Darwin 24.3.0 / arm64；Node v24.2.0，V8 13.6.233.10-node.17，无额外 Node 参数。基于 `f93cd2e` 的开发工作树（含未提交的预算实现），主会话接线完成并运行 `npm run build` 后复测；本表**不代表真实 TTY 验证**。

默认负载热身后 9 次的中位数：

| 预算 | 排版路径中位数 ms | 实际历史行数 | ANSI UTF-8 字节 |
| --- | ---: | ---: | ---: |
| 全量（0） | 95.513 | 15,323 | 2,717,277 |
| 500 | 3.238 | 500 | 89,492 |
| 1,000 | 6.320 | 1,013 | 180,251 |
| 2,000 | 13.101 | 2,037 | 361,571 |

测量时的指纹（SHA-256）：

```text
JSON.stringify(fixture):
d0183c38f7faf0db7738e7f0993274cb6447d026bea70e716e72ed474cf9704b
dist/src/render/transcript-renderer.js:
7d4bced01bfadd8d0f4e97b1a24705458c4d0d7901766c2f1dff304797945d89
```

此样本中 500 档恰好落在块边界；1,000/2,000 档保留完整边界块后超出预算，符合软预算而非硬截断语义。窄屏快速校验（48 列、16 轮）得到全量 1,345 行、500 档 501 行、1,000 档 1,034 行、2,000 档 1,345 行；1 轮的小历史四档均为 55 行。不同 Node/V8、主题、宽度、机器负载及渲染实现会改变耗时或输出，表格不是跨机器承诺。

## 不要混淆排版、journal 与真实终端

| 阶段 | 本次基准是否计入 | 另行测量时的边界 |
| --- | --- | --- |
| journal 读取、校验、JSONL 重放、安装 compaction 活跃区 | 否；无文件 I/O | 分别记录文件字节数、有效/活跃记录数、缓存状态及读取/重放耗时；预算不会免去恢复所需的 journal 工作。 |
| 主会话身份恢复、过滤、分组、历史排版与 ANSI 拼接 | 是 | 只限当前驻留快照；不含配置读盘、banner/瞬时提示、in-flight/shell 重投影、footer 或光标恢复。 |
| stdout 写入、背压、终端解析/绘制、scrollback 更新 | 否；只打印小型报告 | 必须在真实 TTY 独立测量，记录终端软件/版本、尺寸与 scrollback 设置；`write` 返回或管道吞吐量不是画面完成时间。 |

若另测恢复总耗时，应把阶段明示拆开；真实 journal 或真实终端的值不能冠以此合成 fixture 的结果。OpenSpec 设计中的私人会话数字仅是前期方向性观察，本表不重用它们，也不把排版缩短倍数当作端到端 `/resume` 加速倍数。集成完成后仍需独立验证真实 TTY 的 resize、配置刷新、流式恢复、光标和清理行为；不以绝对毫秒值设 CI 门槛。
